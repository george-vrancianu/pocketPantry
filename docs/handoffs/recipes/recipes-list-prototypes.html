Recipes list, round 1

Three directions for /recipes. All three keep today's behaviour: search plus Cuisine and Method filters, Base Recipes by default, Variants joining the list once a search or filter is active. Try the search box and chips in each phone. Sample recipes mirror the catalog seed; a few family Variants are added to show the badge.

AGrouped list
  • Closest to the Pantry page: one white table, rows with an initial tile coloured by cuisine, title, meta line, chevron.
  • Variants shown under their base as small chips without filtering; a base row's pill tells the count. Family Recipes sit first under their own label.
  • Filters are chips that open a picker sheet (cuisine, method). Uses only today's list data.
BRecipe cards
  • One card per Base Recipe with a display title, cuisine · method eyebrow and three fact cells: total time, difficulty, servings.
  • The card lists its Variants inline (title, cuisine · method) so a family can see the whole tree without opening it.
  • Search is behind the header action, as in the original handoff mock; chips scroll horizontally. Uses only today's list data.
CCook tonight first
  • A Cook tonight carousel on top from the existing /recipes/cook-tonight endpoint: accent card when the Pantry covers it, white card when one ingredient is missing, with "uses N expiring" chips.
  • Below it the full list with a compact time column. Rows that appear in Cook tonight get a status pill; this join can be done client-side by recipe id, so no API change is needed for what is shown here.
  • Showing coverage on every row (have/needed bar) would need the browse endpoint to return match data.
